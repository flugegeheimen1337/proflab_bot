# Anonymous Group Chat

Архитектура, ограничения Telegram Bot API и выбранный режим.

Дата проверки API: 23 ноября 2026 (Asia/Dubai). Ориентир — Bot API 10.5 от 22 ноября 2026 и aiogram 3.34.

## Три варианта

Режим B включён и является основным. Режимы A и C написаны, но выключены флагами. Их можно включить без переписывания бота.

### Режим B — личный чат. Основной

Человек пишет боту в личные сообщения. Бот проверяет, что человек состоит в выбранной группе и может отправлять такой тип контента, ставит сообщение в очередь и публикует его от имени бота с постоянным псевдонимом.

Так устроена обычная переписка: текст, фото, видео, документ, ответ, удаление своего сообщения, жалоба. Имя автора в группе не появляется, потому что в группу пишет только бот.

Группу бот сам не угадывает. Bot API не отдаёт список общих групп пользователя. Группа появляется после `/link_group` от администратора группы, после события `my_chat_member` или из `DEFAULT_GROUP_ID`.

Проверка `getMe` этого бота показала `can_read_all_group_messages=false`: privacy mode включён. Для режима B это нормально. Бот видит команды в свой адрес, ответы на свои сообщения и личные сообщения. Обычные реплики группы он не получает, и отключать privacy не нужно. Режим C при включённом privacy чужие сообщения не увидит. Ради перехвата privacy выключать не стоит: бот начнёт получать весь чат.

### Режим A — скрытая команда `/anon`. Выключен

`EPHEMERAL_MODE_ENABLED=false`.

С 14 июля 2026 (Bot API 10.2) у `BotCommand` есть `is_ephemeral`. Если команда зарегистрирована как ephemeral в области групп, клиент показывает её только отправителю и этому боту. В aiogram поле есть с версии 3.30.

Ограничения, из-за которых режим не включён по умолчанию:

- В этом окружении нельзя проверить Android, iOS и Desktop. Поведение клиентов не подтверждено.
- У ephemeral-сообщения `message_id` всегда 0. Уникальный адрес — `ephemeral_message_id`. Если его нет, команда пришла как обычная и её мог увидеть чат. Такой текст бот не публикует повторно: повтор только скопировал бы уже видимое сообщение.
- Команда ловит только текст. Подпись к фото командой не является. Медиа идут через личный чат.
- Ответ бота в ephemeral-окне не гарантирован, особенно если клиент отправителя офлайн. Для обычного бота окно короткое, порядка 15 секунд после действия. Админ-бот может слать ephemeral шире, но доставка всё равно не гарантирована.
- Команду `/anon` нельзя вешать на область личных чатов и на scope по умолчанию: группы наследуют такие команды, и флаг ephemeral может не примениться. При выключенном флаге бот удаляет команды области всех групп.
- Старый клиент отправит `/anon` обычным сообщением. Обработчик тогда пишет человеку в личку и ничего не дублирует в группу.

Включать режим имеет смысл только после ручной проверки на телефонах и компьютере. Даже тогда видимая команда без `ephemeral_message_id` не публикуется.

### Режим C — перехват сообщения в группе. Выключен

`INTERCEPT_MODE_ENABLED=false`. Роутер даже не подключается.

Бот может получить обычное сообщение, удалить его и опубликовать заново. До удаления имя автора может быть видно. Это не анонимность. Модуль лежит отдельно, при включении пишет предупреждение администраторам и в лог. Если удалить сообщение не удалось, бот не публикует его повторно.

## Поток публикации

`MessageService.accept` проходит один путь для личного чата и для включённых экспериментальных режимов:

1. Повтор того же `update_id` или той же тройки `(source_chat_id, source_user_id, source_message_id)` возвращает уже сохранённое сообщение и в очередь его не ставит.
2. Пользователь есть в базе. Удалённый профиль не восстанавливается сам: нужен `/start`.
3. Нет общей блокировки и блокировки в этой группе.
4. `getChatMember`: человек может отправить этот тип, и сам бот может писать в группу. Ответ кэшируется в Redis на 45 секунд.
5. Антиспам: число сообщений за минуту, длина, тип, размер файла, глубина очереди человека.
6. Псевдоним создаётся один раз на пару «человек + группа».
7. Ответ ищется по коду из кнопки или по `reply_to_message`.
8. Строка сохраняется со статусом `queued`, затем ставится задание `deliver-{uuid}`.
9. Воркер берёт блокировку, ждёт слот группы, отправляет сообщение и пишет `telegram_message_id` и статус `published`.

Связь хранится так: внутренний id, публичный код, `telegram_message_id`, группа, автор, псевдоним, ответ, источник, статус, время.

Ответ в группе идёт через `reply_parameters` и `allow_sending_without_reply`. `forwardMessage` и `copyMessage` не используются: у пересылки виден источник, а у копии могут остаться сущности вроде `text_mention`.

Текст уходит как HTML: псевдоним жирный, тело экранировано. Фото уходит по `file_id`. Видео и документы бот скачивает и заливает заново с нейтральным именем (`file.mp4`, `file.pdf`). Расширение вне белого списка становится `file.bin`. Файл больше 15 МБ отклоняется: облачный Bot API отдаёт файл примерно до 20 МБ. Альбомы не поддерживаются.

Кнопки под публикацией: ссылка `https://t.me/<bot>?start=r_<код>` и подписанная кнопка «Пожаловаться». Удаление своего сообщения — отдельная подписанная кнопка в личном подтверждении. Подпись — HMAC-SHA256, в callback кладётся усечённый код, весь callback не длиннее 64 байт.

## Очередь и лимиты

У каждой группы свой слот отправки. По умолчанию пауза 1100 мс и не больше 20 публикаций в минуту. Входящий лимит человека — 5 сообщений в минуту, в очереди не больше 10 его сообщений. Три лишних всплеска за час дают временную блокировку на 600 секунд. Числа меняются в `chat_settings` командой `/spam_set`.

`RetryAfter` и сетевая ошибка возвращают задание в arq с паузой. После исчерпания попыток строка становится `failed`, пишется dead-letter и короткое уведомление администраторам. Секреты и тело сообщения в эту запись не кладутся.

Повтор после рестарта: первое задание имеет стабильный id, восстановление ищет статусы `pending`, `queued`, `sending` старше 20 секунд и ставит новое задание. Повторную отправку держит Redis-блокировка на id сообщения. Полностью исключить дубль нельзя, если процесс умер после успешного `sendMessage` и до записи `telegram_message_id`: у Bot API нет ключа идемпотентности отправки.

Глубина очереди группы смотрится из Redis. При глубине от 30 администраторам уходит предупреждение не чаще раза в 10 минут.

Мгновенной публикации при лимите Telegram нет.

## Данные

PostgreSQL, SQLAlchemy 2 async, Alembic.

- `chats` — telegram id группы, публичный код, название, активность.
- `users` — telegram id (может быть пустым после полной отвязки), блокировка, признак что бот заблокирован, время удаления, выбранная группа, код ожидаемого ответа. Username и имя не хранятся.
- `chat_settings` — лимиты группы.
- `aliases` — номер и подпись, уникальные внутри группы и уникальные для человека в группе.
- `messages` — публичный код, автор, псевдоним, тип, тело, file id, нейтральное имя, источник, update id, ответ, telegram message id, статус.
- `reports` — одна жалоба на сообщение от человека.
- `chat_bans` — блокировка в группе, срок, кто поставил.
- `admin_actions` — действие, псевдоним, группа, короткая деталь. Telegram ID цели не пишется.
- `broadcasts`, `broadcast_runs`, `broadcast_deliveries` — рассылка, слот запуска, адресат как `user:<uuid>` или `chat:<uuid>`.
- `failed_jobs` — имя задания и id, без текста сообщения.
- `callback_receipts` — id callback, чтобы нажатие не исполнилось дважды.

`/delete_my_data` ставит `erased_at` и сбрасывает выбранную группу, но telegram id оставляет: иначе блокировка обходится новым `/start` на чистую запись. `/purge` у администратора обнуляет telegram id. Старые сообщения остаются под псевдонимом. Новый `/start` после purge создаёт другого пользователя и другой псевдоним.

## Рассылки и статистика

`BroadcastService`: в группу, в личку тем, кто запускал бота, разово по времени, повтор daily или weekly. Слот запуска уникален. Повторный проход не шлёт тому, у кого уже есть доставка. Личка не уходит удалённым, заблокированным и тем, кто заблокировал бота. `Forbidden` помечает `bot_blocked`.

Отчёт администратору: адресаты, отправлено, ошибки, заблокировали бота. Времени чтения нет.

`/stats`, `/stats_today`, `/stats_week`, `/stats_month` и CSV за 30 локальных дней. Часовой пояс — `TIMEZONE`, по умолчанию `Europe/Moscow`. В CSV нет telegram id. Прочтения не считаются: Bot API их для участников группы не даёт.

Команды статистики и модерации доступны только id из `ADMIN_IDS`. Каждое действие проверяется заново. `/reveal` показывает telegram id только при `REVEAL_TELEGRAM_IDS=true` и пишет в журнал `allowed` или `denied`, без самого id.

## Безопасность

- Токен, секрет callback и токен API только в окружении. В логах токен вида `123456:AA...` заменяется.
- Логгеры aiogram и aiohttp приглушены, чтобы текст апдейта не попадал в лог.
- PostgreSQL и Redis в Compose открыты только на `127.0.0.1`. API слушает `127.0.0.1:8080`. Без `ADMIN_API_TOKEN` маршрут статистики отвечает 404.
- Резервная копия: `scripts/backup.sh`. Восстановление: `scripts/restore.sh`.

## Состав процесса

- `python -m app.main` — long polling, health на порту 8081.
- `python -m app.worker_main` — arq, health на 8082. В `on_startup` пул arq не перезаписывается: свой Redis лежит в `app_redis`.
- `python -m app.api_main` — FastAPI, `/health` и `/api/v1/stats`.
- Миграции — отдельный одноразовый сервис `migrate`.

Сессия SQLAlchemy открывается явно. Контекстный `async with session_factory()` начинает транзакцию, и внутренний commit с ним конфликтует, поэтому так не делается.

## Что проверить руками

Автотесты гоняют сервисы на SQLite и поддельном Telegram. Живой клиент они не заменяют.

1. Администратор группы пишет `/link_group`.
2. Участник нажимает `/start`, выбирает группу, пишет текст. В группе автор — бот, подпись — «Аноним #…».
3. Второй участник жмёт «Ответить» и пишет в личку. В группе это reply.
4. Кнопка «Удалить» снимает только своё сообщение.
5. Жалоба приходит администратору без telegram id автора в тексте группы.
6. Если включаете `/anon`, проверьте Android, iOS и Desktop: команда не видна другим, а обычная видимая команда не публикуется повторно.
