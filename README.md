# Anonymous Group Chat

Бот для общей Telegram-группы. В группе сообщения выходят от имени бота с постоянным псевдонимом «Аноним #104». Имя, username и Telegram ID автора в группу не попадают.

Это не абсолютная анонимность. Текст видят участники. Его обрабатывают Telegram и сервер бота. Подробности: [docs/privacy.md](docs/privacy.md). Архитектура и ограничения API: [docs/architecture.md](docs/architecture.md).

## Какой режим включён

| Режим | Как устроено | Сейчас |
| --- | --- | --- |
| B. Личный чат | Человек пишет боту, бот публикует в группу | включён, основной |
| A. Скрытая команда `/anon` | В группе пишете `/anon` и текст. Публикация идёт в эту же группу и тему | включён |
| C. Перехват сообщений группы | Удалить чужое сообщение и опубликовать заново | выключен, `INTERCEPT_MODE_ENABLED=false` |

Режим C анонимности не даёт: имя может быть видно до удаления. Его не стоит включать для обычной группы.

В группе команда пишется так: `/anon текст`. Публикация идёт в эту же группу и в эту же тему. Свой псевдоним в каждой группе отдельный. Публикация происходит, когда Telegram прислал команду как скрытую. Обычную видимую команду бот не копирует в группу. Фото и файлы по-прежнему отправляются в личный чат.

## Перед запуском

Токен бота в репозиторий не кладётся. Если токен уже светился в переписке, отзовите его в @BotFather и впишите новый только в локальный `.env`.

```bash
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

В `.env` заполните `BOT_TOKEN`, `CALLBACK_SECRET` (не короче 16 символов) и `ADMIN_IDS` — telegram id администраторов через запятую. Пароль Postgres замените в `POSTGRES_PASSWORD` и в `DATABASE_URL`.

`BOT_USERNAME` можно оставить пустым: при старте бот берёт его из `getMe`.

## Запуск на Ubuntu

Нужны Docker и Docker Compose.

```bash
docker compose up -d --build
docker compose ps
./scripts/diagnose.sh
```

Сервисы: `postgres`, `redis`, одноразовый `migrate`, `bot` (health `127.0.0.1:8081`), `worker` (health `127.0.0.1:8082`), `api` (`127.0.0.1:8080`). Postgres и Redis наружу смотрят только на localhost.

Обновление:

```bash
git pull
docker compose up -d --build
```

Миграции выполняет сервис `migrate` до старта бота и воркера.

Остановка:

```bash
docker compose stop
```

## Как подключить группу

1. Бот уже добавлен в группу и может отправлять сообщения. Если участникам писать нельзя, дайте боту право публиковать. Privacy mode в @BotFather оставьте включённым: бот не должен читать обычные реплики группы. Команду `/link_group` он видит и так.
2. Администратор группы отправляет `/link_group`. В режиме privacy бот видит команду как `/link_group@username`.
3. Администратор бота из `ADMIN_IDS` один раз пишет боту `/start`, иначе личные отчёты ему не дойдут.
4. Участник пишет боту `/start`, выбирает группу и отправляет текст, фото, видео или один документ.

Альбомы из нескольких файлов не поддерживаются. Видео и документы больше 15 МБ отклоняются: бот заливает их заново без исходного имени файла.

Ответ в группе — кнопка «Ответить», затем сообщение боту в личку. Своё опубликованное сообщение удаляется кнопкой «Удалить» в подтверждении. «Пожаловаться» уходит администраторам.

Если бота добавили давно, событие входа может уже не прийти в polling. Тогда достаточно `/link_group`. Либо укажите `DEFAULT_GROUP_ID`.

Публикация стоит в очереди группы. При лимите Telegram сообщение выйдет позже, не сразу.

## Команды участника

`/start`, `/help`, `/chats`, `/alias`, `/rules`, `/privacy`, `/cancel`, `/delete_my_data`.

`/delete_my_data` отключает отправку. Telegram ID остаётся в базе, чтобы блокировка не сбрасывалась. Повторный `/start` возвращает тот же псевдоним. Полная отвязка id — администраторская команда `/purge`.

## Команды администратора

Только id из `ADMIN_IDS`, только в личном чате.

- `/admin` — меню
- `/stats`, `/stats_today`, `/stats_week`, `/stats_month`, `/export_stats`
- `/groups`, `/queue`, `/complaints`, `/errors`
- `/block 104`, `/block 104 30`, `/unblock 104`
- `/gblock 104`, `/gunblock 104`
- `/reveal 104` — telegram id только при `REVEAL_TELEGRAM_IDS=true`
- `/purge 104` — отвязать telegram id, сообщения в группе остаются
- `/spam`, `/spam_set messages_per_minute 3`
- `/broadcast`, `/broadcasts`, `/broadcast_cancel 8символов`

Ключи `/spam_set`: `messages_per_minute`, `max_message_length`, `spam_block_seconds`, `max_queue_per_user`, `allowed_types`.

Рассылка: аудитория (группа или личные чаты тех, кто нажал `/start`), время (сейчас, дата `2026-11-24 15:00`, `daily 15:00`, `weekly mon 15:00` или `weekly пн 15:00`), текст или одно фото, предпросмотр, подтверждение. Отчёт: адресаты, отправлено, ошибки, заблокировали бота. Прочтений нет.

## Резервная копия

Раз в сутки, от пользователя с доступом к каталогу проекта:

```bash
./scripts/backup.sh
```

Файлы лежат в `backups/` и в git не попадают. Восстановление останавливает bot, worker и api:

```bash
./scripts/restore.sh backups/anonchat-YYYYMMDDTHHMMSSZ.sql
```

## Проверка без Telegram

```bash
python3 -m pip install -e ".[dev]"
python3 -m pytest
```

Тесты покрывают регистрацию, псевдонимы, сохранение и ответы, повтор update, членство, блокировки, очередь, лимит отправки, рассылку, права администратора и отсутствие telegram id в публичном тексте. Живой Bot API они не вызывают.

## Ручная проверка в Telegram

1. `/link_group` в супергруппе.
2. Два участника пишут боту в личку. В группе оба сообщения от бота, псевдонимы разные и не меняются между сообщениями.
3. «Ответить» строит reply на исходное сообщение.
4. «Удалить» снимает только своё.
5. Участник без прав на медиа не может отправить фото.
6. Для режима A: на Android, iOS и Desktop команда `/anon текст` не видна остальным, а обычное видимое `/anon` не появляется в группе второй раз.

## Диагностика

`./scripts/diagnose.sh` показывает состояние Compose, health API и хвост логов.

Бот не видит группу: отправьте `/link_group` ещё раз. Сообщение зависло в очереди: `/queue` и логи `worker`. Ошибка Telegram `retry after` означает, что слот группы занят, это ожидаемая пауза. `group_unavailable` — у бота нет права писать.
